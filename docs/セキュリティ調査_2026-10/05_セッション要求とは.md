# セッション要求とは

このアプリのログインは Google アカウントで、メールアドレスが `@hitotsunokai.jp` で終わる人だけが通る（`auth.config.ts`）。

## いま職員のブラウザに残っているもの

ログインに成功すると、ブラウザに「この人はログイン済み」というクッキーが残る。次からの画面操作では、ブラウザがそのクッキーを自動で付ける。職員が毎回パスワードを入れているわけではない。この「ログイン済みの印」がセッションである。

印が付いていない通信は、サーバの入り口 `middleware.ts` が止めている。

- 画面を開く通信は、ログイン画面へ戻す（本番では 2026-10-26 に 307 を確認）
- 利用者一覧などの API は、データを返さず 401 を返す（同じ日に `/api/facilities` で確認）

クッキーの値そのものはここには書かない。

## 「セッションを要求する」が指す状態

API の関数が、データベースを読む前・入出金を書く前に、同じ印が付いているかを自分でも見ること。

今は入り口の `middleware.ts` だけが見ている。利用者一覧や入出金を処理する関数は、リクエストがそこまで届いた時点でログイン済みだと見なして仕事を始める。

印が無いリクエストに対して、API 自身が 401 を返してデータベースに触らない状態が「セッションを要求している」状態である。印があるリクエストは、今と同じように処理される。ログインの仕方も、ログイン後の操作も変わらない。

空床の公開 API は別で、職員のログインではなく API キーを見ている。そこは対象外。
