# 認証を API でも見ても、ログイン制限には当たらない

確認日: 2026-10-26。根拠は `middleware.ts` と `lib/apiRateLimit.ts`。

## 1分に2回の対象

数えるのは、同じ IP から次のパスへ来た通信だけである。

- `/api/auth/signin`
- `/api/auth/signin/` で始まるパス（Google へ進む `/api/auth/signin/google` を含む）

数えないもの:

- Google から戻る `/api/auth/callback`（ログイン完了の通信）
- ログイン済みかを画面が確認する `/api/auth/session`
- 施設一覧や入出金などの業務 API（こちらは別枠で 1分に150回）

普段の入力や一覧表示は業務 API なので、2回の枠は減らない。2回の枠を使うのは、ログイン画面を開くときと、Google のボタンを押すときである。これは今も同じである。

## API 側の確認が足す通信

API の関数がログイン済みの印を見る処理は、すでに届いているその1回の通信の中で行う。ブラウザがログイン画面や Google へもう一度アクセスする動きにはしない。印が無いときは、今の入り口と同じく JSON の 401 を返す。ログイン画面へ転送しない。

画面側のコードも、API が 401 だったときに自動で Google ログインへ飛ばす処理は無い。ログインはヘッダーのボタンを押したときだけ `signIn('google')` が走る。

したがって、ログイン済みの職員が普段どおり使う分には、1分2回の制限に新たに引っかかる経路は無い。
