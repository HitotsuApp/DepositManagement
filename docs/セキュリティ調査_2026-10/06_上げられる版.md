# 上げられる版

確認日: 2026-10-26。npm 上の版と、インストール済み `@cloudflare/next-on-pages` 1.13.16 の peer を見た。`package.json` はまだ変えていない。ビルドもしていない。

本番 `https://depositmanagement.pages.dev` は Worker が動いている。未ログインの `/` はログイン画面へ 307、`/api/facilities` は 401。配信されている Next.js の版番号はレスポンスからは分からない。リポジトリのロックは 14.2.16。

## 結論

| 候補 | 扱い |
| --- | --- |
| 14.2.35 | 今の Cloudflare Pages と next-on-pages のまま上げる版。認証回避（CVE-2025-29927）と 2025年12月のサービス停止（CVE-2025-55184）まで塞ぐ |
| 15.5.2 以下 | 上げない。next-on-pages の peer 上限は 15.5.2 だが、15.5.2 は React2Shell の修正（15.5.7）より前。15 系に乗ると、今は対象外の遠隔コード実行の範囲に入る |
| 15.5.28 | 2026年10月14日時点の 15 系の修正済み版。載せるには OpenNext（`@opennextjs/cloudflare` 1.20.13）へ配信方法を変える |
| 16.4.1 | 同じく修正済みの 16 系。OpenNext は受け付ける。今の `middleware.ts` からの段差は 15.5.28 の方が小さい |

## 14.2.35 が今のビルドに載るか

next-on-pages 1.13.16 の peer は `next >=14.3.0 && <=15.5.2`。14.2.35 はこの下限より下である。今入っている 14.2.16 も同じで、インストールは通っている。パッケージ内を探した範囲では、起動時にこの peer で版を拒否する処理は見当たらない。1.13.3 以降は Next.js 14.2.8 以降のビルド差分に合わせた修正が入っている。

したがって 14.2.35 は、今と同じ `npx @cloudflare/next-on-pages` でビルドできる見込みがある。npm は peer の警告を出す。14 系はこの版が最後で、2026年5月以降の修正は入っていない。React は 18 のままなので、React2Shell の対象には入らない。

## 15.5.28 に行くときに変わるもの

修正を 2026年5月と10月まで含める版は、npm 上に 15.5.28 と 16.4.1 がある。OpenNext 1.20.13（2026-10-21 公開）の peer は `next >=15.5.28 <16 || >=16.4.1` と `wrangler ^4.148.0`。今の wrangler は 4.105.0 なので、アダプタと一緒に上げる。

OpenNext は Next.js の Node.js ランタイムを Workers で動かす。next-on-pages は Edge ランタイムしか受け付けない。このリポジトリの API と一部ページは、その制約で `export const runtime = 'edge'` になっている。OpenNext へ移すときは、この指定を外して Node.js ランタイムで動くことを確認する。Prisma、Neon の WebSocket、PDF 生成は、Edge 向けにバンドルを避けている箇所なので、載せ替え時の確認点になる。

配信先は Cloudflare Pages（`pages.dev`）から Workers になる。URL の切り替えは版番号の変更とは別の作業である。

vinext は Cloudflare が新しいアプリに勧めているが、Next.js 本体のサーバではなく別実装である。`next` パッケージを 15.5.28 や 16.4.1 にしても、vinext 上ではその修正が入った Next.js が動くわけではない。今回の版上げの受け皿にはしない。

## 推奨

1. まず 14.2.35。配信の仕組みを変えずに、認証回避と 2025年12月のサービス停止を塞ぐ。
2. 15.5.2 には上げない。
3. 2026年5月以降まで含めるなら、OpenNext と wrangler 4.148 以降へ移し、Next.js は 15.5.28 にする。16.4.1 は修正済みのもう一方の線で、第一候補にはしない。
