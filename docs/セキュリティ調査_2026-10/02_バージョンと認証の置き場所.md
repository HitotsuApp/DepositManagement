# バージョンと認証の置き場所

## ロックされている版

`package.json` は `next: ^14.2.16`。実際に解決されている版は `package-lock.json` の `node_modules/next` で **14.2.16**。npm はこの版を非推奨とし、2025-12-11 のセキュリティ更新を参照している。

| パッケージ | ロックされた版 | メモ |
| --- | --- | --- |
| next | 14.2.16 | 14 系の最終セキュリティ修正は 14.2.35（2025-12-12）。14 はサポート終了 |
| react / react-dom | 18.3.1 | React 19 の Server Components 実装ではない |
| next-auth | 5.0.0-beta.30 | Auth.js v5 のベータ。peer は Next.js 14 / 15 / 16 |
| @cloudflare/next-on-pages | 1.13.16 | `pages:build` スクリプトがこれを使う |

`next.config.js` に `use cache` や Cache Components の有効化はない。ソース内に `"use server"` と `next/image` はない。画面は App Router（`app/`）で、API は `export const runtime = 'edge'`。

## ログインが効く場所

`middleware.ts` が未ログインの API に 401 を返し、画面はサインインへ戻している。レート制限と海外 IP の拒否も同じファイルにある。

API ルートは 27 ファイル。ハンドラ内で資格情報を見ているのは次の 2 つだけ。

- `app/api/auth/[...nextauth]/route.ts`（ログインそのもの）
- `app/api/public/vacancy/route.ts`（`VACANCY_API_KEY`。ミドルウェアのログイン対象外）

残りはハンドラにセッション確認がない。例として `app/api/transactions/route.ts` の POST は、検証済みの JSON を受け取ると入出金を作成する。`app/api/residents/route.ts` の GET は利用者一覧を返す。

`app/layout.tsx` と `app/(main)/layout.tsx` にもサーバ側のログイン確認はない。画面の表示データは、ミドルウェアを通過したあとの API 呼び出しに依存している。

したがって、ミドルウェアが実行されないリクエストでは、レート制限もログインも掛かっていない状態で API に到達する。

## 本番側で未確認のこと

Cloudflare は CVE-2025-29927 向けの WAF ルールを出しているが、初期状態では有効にならない（オプトイン）。無料プランではマネージドルールではなく、同ヘッダーを落とすカスタムルールが案内されている。このゾーンで有効かは、リポジトリからは分からない。

`wrangler.toml` はリポジトリにない。デプロイ先が `next-on-pages` かどうかはスクリプトの存在から推定している。
