# 今やることと、後でやること

確認日: 2026-10-26

2026-10-26 に、今できる範囲をコードへ入れた。Next.js は 14.2.35。業務 API 35 ハンドラは `requireApiSession` でログイン済みかを見る。空床の公開 API とログイン API は対象外。OpenNext への置き換えはまだしていない。詳細は `09_実施した修正.md`。

## 今の穴を塞ぐのに OpenNext は要らない

ログインを飛ばされる問題（CVE-2025-29927）と、2025年12月のサービス停止は、今の Cloudflare Pages と `next-on-pages` のまま **Next.js 14.2.35** で塞げる。

あわせて、利用者・入出金・インポート・印刷の API が、入り口の `middleware.ts` だけでなく自分でもログイン済みの印を見る。職員の操作は変わらない。印が無いリクエストは、その API が 401 を返してデータベースに触らない。

ログを増やすことは、この穴を塞ぐ手段ではない。2026年6月のように海外からの走査が来たとき、拒否された通信を後から見るのには役立つ。データに触らせないのは、版と、API 自身のログイン確認である。

## OpenNext は、その次の版に進むとき

`@cloudflare/next-on-pages` は開発が終わり、案内先は OpenNext になっている。このアダプタが受け付ける Next.js 15 の上限は 15.5.2 で、乗っ取り系の修正（15.5.7）より前である。15.5.2 へ上げると、今は対象外の範囲に入る。

2026年5月以降の修正が入った 15.5.28 を載せるには、配信を OpenNext に変える。今の Pages ビルドのままでは届かない。

## 2026年3月に止まった理由

OpenNext 対応のコミットを Cloudflare Pages でビルドしたとき、Pages が `wrangler.json` を自分の設定として読めず止まっている。メッセージは、Pages 用なら `wrangler.toml` ではないか、というものだった。その後は OpenNext を見送り、`next-on-pages` 1.13.16 と wrangler 4.105.0 に固定して、今の Pages ビルドを通している。

この固定のあいだは、今の配信方法で預かり金システムは動く。新しい Next.js の修正は、この固定のままでは取り込めない。
